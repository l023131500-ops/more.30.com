# הוראות בנייה מלאות — מערכת ניהול מכירות משקפיים

> **מה זה המסמך הזה:** הנחיה מלאה, מוכנה להעתקה, עבור **Claude Code** או **Lovable**
> (או כל מפתח אנושי), לבניית המערכת מאפס בלי לפספס אף כפתור ואף פונקציה.
> העתיקו את כל התוכן שמתחת לקו כפרומפט אחד.
>
> אם אתם עובדים על **הקוד שכבר קיים בריפוזיטורי הזה** — אין צורך בפרומפט; המערכת בנויה.
> השתמשו במסמך כרשימת בדיקה (checklist) לוודא שכל דרישה מומשה.

---

## הוראות למפתח / ל-AI

בנה מערכת ניהול מכירות משקפיים, **בעברית מלאה, ממשק RTL**, לניהול מכירות שמתקיימות
באולמות בשכונות ברחבי הארץ. אין להוסיף טקסטי הסבר ארוכים במסכים — המערכת תפעולית.
שם הארגון: **"אופטיקה לכל כיס" בשיתוף ארגון "בקלות"** (ניתן לשינוי בהגדרות).

### דרישות טכניות

* עברית מלאה, `dir="rtl"`, `lang="he"`.
* אחסון נתונים מתמיד — IndexedDB או בסיס נתונים (Supabase/Postgres) לפי הפלטפורמה.
* חובה: המרת תאריכים עברי↔לועזי **בקוד המערכת** (לא בשירות חיצוני), כולל חישוב חגים.
* חובה: ייצוא וייבוא של `.xlsx` ו-`.csv` (עם BOM, כדי שעברית תיפתח תקין ב-Excel).
* חובה: החזקת מספרי טלפון כטקסט (לא לאבד אפס מוביל).
* עיצוב נקי, כרטיסים, טבלאות עם גלילה אופקית, מותאם למחשב וטאבלט.

## מסך 1 — דשבורד מרכזי: לוח שנה

- [ ] לוח שנה חודשי מלא, **עברי־לועזי**: בכל תא מספר היום הלועזי **ובנוסף** התאריך העברי בגימטריה (לדוגמה `כ״ג אב`).
- [ ] כותרת: שם החודש הלועזי + שנה, ומתחת — טווח החודשים העבריים (`אב – אלול תשפ״ו`).
- [ ] ניווט: **הקודם / החודש / הבא** + בורר חודש ובורר שנה. מעבר החודשים אוטומטי ורציף.
- [ ] שמות ימי השבוע בעברית, בסדר RTL: ראשון בימין → שבת בשמאל.
- [ ] **קוד צבעים לכל יום:**
  - [ ] 🟩 **ירוק** — היום פנוי למכירה.
  - [ ] 🟦 **כחול** — יש מכירה ביום זה.
  - [ ] 🟥 **אדום** — היום סומן כ**לא פנוי** למכירה.
  - [ ] ⬜ **אפור** — **יום שישי, שבת, וימי חגי ישראל** — ללא מכירות.
- [ ] היום הנוכחי מסומן במסגרת בולטת.
- [ ] **בכל יום שיש בו מכירה — מוצג בתא מיקום המכירה**: עיר · שכונה, שם האולם, רחוב ומספר.
- [ ] **כפתור `+` בכל תא — "מכירה נוספת"**: פותח מכירה נוספת באותו יום.
- [ ] **ביום עם 2 מכירות** — מוצגות שתי שורות נפרדות עם המיקום של כל אחת, ותג "2 מכירות".
- [ ] לחיצה על יום עם מכירה אחת → כניסה ישירה לדשבורד המכירה.
- [ ] לחיצה על יום עם מספר מכירות → חלון בחירה + כפתור "מכירה נוספת".
- [ ] לחיצה על יום ריק → חלון: פתיחת מכירה / סימון כלא פנוי (אדום) / הוספת הערה ליום.
- [ ] שורת מחוונים חודשית מעל הלוח: מכירות · לקוחות · הכנסות · הוצאות · רווח + % · יתרה לגבייה.
- [ ] מקרא צבעים מתחת ללוח.
- [ ] טבלת "מכירות קרובות" מתחת ללוח, עם כפתור פתיחה.

### חגי ישראל — חובה לחשב אוטומטית

יש לחשב מהלוח העברי (לא לקודד תאריכים לועזיים קבועים!) ולסמן באפור:

| קטגוריה | מועדים | חוסם כברירת מחדל |
|---|---|---|
| יום טוב | ראש השנה (2 ימים), יום כיפור, סוכות א׳, שמיני עצרת/שמחת תורה, פסח א׳, שביעי של פסח, שבועות | ✔ |

| צום מרכזי | תשעה באב | ✔ |
| תענית | צום גדליה, י׳ בטבת, תענית אסתר, י״ז בתמוז | ✘ |

**כללי דחייה שחובה לממש:** צום שחל בשבת נדחה ליום ראשון · תענית אסתר שחלה בשבת מוקדמת ליום חמישי ·

**בשנה מעוברת** — פורים חל באדר ב׳, וחודש אדר א׳ מוצג כ"אדר א׳".

## מסך 4 — צינתוקים (API ימות המשיח)

- [ ] **בהגדרות** — מקום להזין ולשמור: **מספר המערכת של הטלפון** ו**מפתח ה-API**,
      וכן מספר מזוהה יוצא (callerId), משך צינתוק, קובץ הודעה, ואופן החיבור.
- [ ] **כפתור "שמירה ובדיקת חיבור"** שמבצע `GetSession` ומציג את התשובה.
- [ ] **כפתור שליחת צינתוק במסך יום המכירה** — לכל הלקוחות או רק למסומנים.
- [ ] **כפתור שליחה מרשימת הלקוחות לפי אזור** (מסך מכירות קודמות).
- [ ] סוגי שליחה: **צינתוק** (`RunTzintuk`) · **קמפיין השמעת הודעה** (`RunCampaign`) ·
      **SMS** (`SendSms`) · **אישור הגעה** (תשתית).
- [ ] **מצב "הרצת בדיקה"** — רישום ביומן ללא שליחה בפועל.
- [ ] נרמול מספרי טלפון: `+972`/`00972` → `0`, הסרת תווים, סינון כפילויות ומספרים לא תקינים.
- [ ] **מסך נפרד שמציג את כל האנשים ואם הם שמעו את ההודעה** — סטטוס לכל נמען,
      עמודת "שמע", עמודת "אישור הגעה", עדכון ידני, ורענון אוטומטי מה-API.
- [ ] ייצוא לאקסל של כל קמפיין ושל הדוח המרוכז.
- [ ] **תשתית קמפיין אישורי הגעה** — סוג קמפיין, שדה `rsvp` לכל נמען, מחוון "אישרו הגעה",
      מתג הפעלה + שדה שלוחת IVR בהגדרות.

**פרטי ה-API (חובה לממש לפי זה):**

```
POST https://www.call2all.co.il/ym/api/{Action}
Content-Type: application/x-www-form-urlencoded
token=<מספר מערכת>:<סיסמת API>
```

| Action | פרמטרים |
|---|---|
| `GetSession` | `token` |
| `RunTzintuk` | `token`, `callerId`, `phones` (מופרד בפסיקים), `TzintukTimeOut`, `tzintuk_your_id` |
| `RunCampaign` | `token`, `callerId`, `phones` (JSON `{"0501234567":"טקסט"}`), `withSMS`, `ivrPath` |
| `SendSms` | `token`, `phones`, `message`, `from` |
| `GetCampaignReport` | `token`, `campaignId` |

- [ ] **חובה: שרת ביניים (proxy)** לעקיפת CORS ולהסתרת המפתח, עם רשימת פעולות מותרת סגורה,
      ואפשרות להזרקת הטוקן ממשתני סביבה בצד השרת.

## בדיקות קבלה

1. פתיחת המערכת → הלוח מציג את החודש הנוכחי, עברי ולועזי, שישי/שבת באפור.
2. חודש שיש בו חג (למשל תשרי/ניסן) → ימי החג אפורים עם שם המועד.
3. פתיחת מכירה ביום ירוק → היום הופך כחול ומציג את המיקום.
4. `+` על אותו יום → נוצרת מכירה שנייה, והתא מציג שתי שורות ותג "2 מכירות".
5. הוספת 3 לקוחות → הסיכומים למעלה מתעדכנים (סה״כ, שולם, נותר).
6. סימון "שולם" → סכום התשלום מתמלא, המחוון מתעדכן.
7. שינוי הוצאות → הרווח והרווחיות מתעדכנים מיידית.
8. הגדרות טבלה → הוספת עמודה חדשה → מופיעה בטבלה ובייצוא.
9. הורדת אקסל → נפתח ב-Excel בעברית, RTL, טלפון עם אפס מוביל.
10. ייבוא אקסל → מיפוי עמודות → הרשומות נוספות.
11. שליחת צינתוק במצב בדיקה → נרשם ביומן עם כל הנמענים.
12. רענון הדף → כל הנתונים נשמרו.
13. כל הדוחות נטענים ומייצאים.

## אפשרות חלופית — Lovable

אם בונים ב-Lovable, השתמשו באותו מסמך כפרומפט, ובנוסף:

* בקשו **Supabase** לאחסון (טבלאות: `sales`, `customers`, `sale_costs`, `tasks`, `notes`,
  `ads`, `campaigns`, `campaign_targets`, `archive_customers`, `day_flags`, `settings`).
* בקשו **Supabase Storage** לקבצי המודעות.
* בקשו **Edge Function** בשם `yemot` שתשמש כשרת הביניים ל-API (לפי סעיף מסך 4).
* הדגישו: **הלוח העברי וחישוב החגים חייבים להיות מחושבים בקוד** ולא בקריאה לשירות חיצוני.
* הדגישו: **RTL מלא** ועברית בכל המסכים.
