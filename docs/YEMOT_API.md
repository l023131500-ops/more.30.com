# חיבור למערכת ימות המשיח — צינתוקים, הודעות ואישורי הגעה

מסמך זה מתאר כיצד המערכת מתחברת ל-API של **ימות המשיח (call2all)**,
מה צריך להגדיר, ואיך מרחיבים לקמפיין אישורי הגעה.

---

## 1. עקרונות ה-API

| נושא | ערך |
|---|---|
| כתובת בסיס | `https://www.call2all.co.il/ym/api` |
| כתובת חלופית | `https://private.call2all.co.il/ym/api` |
| מבנה קריאה | `POST {base}/{Action}` עם גוף `application/x-www-form-urlencoded` |
| אימות | פרמטר `token` בכל קריאה, בפורמט `<מספר מערכת>:<סיסמת API>` |
| דוגמה לטוקן | `077123456:1234` |
| פורמט תשובה | JSON עם השדה `responseStatus` (`OK` / שגיאה) |

> **חשוב:** מספרי הטלפון נשלחים בפורמט ישראלי מקומי — `0501234567`.
> המערכת מנרמלת אוטומטית `+972…` / `00972…` / מספרים ללא אפס מוביל, ומסננת כפילויות ומספרים לא תקינים.

---

## 2. הפעולות שבשימוש המערכת

| Action | תפקיד | פרמטרים עיקריים |
|---|---|---|
| `GetSession` | בדיקת חיבור ותקינות הטוקן | `token` |
| `RunTzintuk` | הרצת **צינתוק** לרשימת מספרים | `token`, `callerId`, `phones`, `TzintukTimeOut`, `tzintuk_your_id`, `sayInfoOnAnswer` |
| `RunCampaign` | קמפיין השמעת הודעה (+SMS אופציונלי) | `token`, `callerId`, `phones` (JSON), `withSMS`, `ivrPath`, `ttsMessage` |
| `SendSms` | שליחת SMS | `token`, `phones`, `message`, `from` |
| `GetCampaignsList` | רשימת הקמפיינים במערכת | `token` |
| `GetCampaignReport` | דוח נמענים לקמפיין | `token`, `campaignId` |

### דוגמאות

**צינתוק:**
```
POST https://www.call2all.co.il/ym/api/RunTzintuk
token=077123456:1234
callerId=0771234560
phones=0501234567,0527654321,0533456789
TzintukTimeOut=6
```

**קמפיין עם SMS:**
```
POST https://www.call2all.co.il/ym/api/RunCampaign
token=077123456:1234
callerId=0771234560
phones={"0501234567":"מכירת משקפיים היום ברמות","0527654321":"מכירת משקפיים היום ברמות"}
withSMS=1
```

**SMS בלבד:**
```
POST https://www.call2all.co.il/ym/api/SendSms
token=077123456:1234
phones=0501234567,0527654321
message=מכירת משקפיים מחר באולמי הדר, רמות, בשעה 17:00
from=0771234560
```

> שמות הפעולות והפרמטרים נבדקו מול התיעוד הציבורי של ימות המשיח.
> אם בחשבון שלכם קיים שם פעולה שונה, ניתן לשנות את כתובת הבסיס בהגדרות,
> ואת שמות הפעולות בקובץ `src/yemot.js` (פונקציות `runTzintuk`, `runCampaign`, `sendSms`).
> הרשימה הלבנה של הפעולות המותרות בשרת הביניים נמצאת ב-`api/yemot.js` (`ALLOWED_ACTIONS`).

## 3. הגדרה במערכת

**הגדרות → חיבור למערכת ימות המשיח**

| שדה | הסבר |
|---|---|
| **מספר המערכת** | מספר הטלפון של המערכת שלכם בימות המשיח (לדוגמה `077-1234567`) |
| **מפתח API / סיסמה** | סיסמת ה-API של המערכת |
| **מספר מזוהה יוצא (callerId)** | המספר שיוצג אצל הנמען |
| **משך צינתוק** | מספר שניות הצלצול (ברירת מחדל 6) |
| **אופן החיבור** | `שרת ביניים` (מומלץ) או `ישירות מהדפדפן` |
| **קובץ ההודעה** | נתיב הקובץ במערכת, לדוגמה `ivr2:/1/000.wav` |
| **טקסט להקראה** | טקסט חלופי ל-TTS |

לסיום — לחצו **"שמירה ובדיקת חיבור"**. המערכת תבצע `GetSession` ותציג את התשובה.

## 4. למה שרת ביניים (Proxy)

קריאה ישירה מהדפדפן ל-`call2all.co.il` עלולה להיחסם ע״י מדיניות **CORS** של הדפדפן,
ובנוסף חושפת את מפתח ה-API בתעבורת הדפדפן.

הפרויקט כולל שרת ביניים מוכן: **`api/yemot.js`**.

* על **Vercel** — הקובץ נטען אוטומטית ככתובת `/api/yemot`, ללא הגדרה נוספת.
* על **Netlify** — יש להעביר ל-`netlify/functions/yemot.js`, והכתובת תהיה `/.netlify/functions/yemot`.
* בסביבה סטטית בלבד (GitHub Pages) — אין תמיכה בפונקציות; יש לבחור `ישירות מהדפדפן`
  או לארח את השרת בנפרד ולהזין את כתובתו בשדה "כתובת שרת הביניים".

### הסתרה מלאה של המפתח (מומלץ בפרודקשן)

הגדירו בשרת משתני סביבה:

```
YEMOT_SYSTEM=077123456
YEMOT_TOKEN=הסיסמה
```

כאשר הם מוגדרים, שרת הביניים **מתעלם** מהטוקן שנשלח מהדפדפן ומשתמש בטוקן שלו,
כך שהמפתח לעולם אינו מגיע לצד הלקוח.

## 5. תשתית אישורי הגעה (RSVP)

הדרישה: לשלוח קמפיין שבו הלקוח מקיש **1 = מגיע היום לקחת את המשקפיים**, **2 = לא מגיע**,
והמערכת תציג מי אישר.

**מה כבר קיים במערכת:**
* סוג קמפיין `אישור הגעה` בחלון השליחה.
* שדה `rsvp` לכל נמען, עם עמודה במסך הפירוט ובכל הדוחות והייצוא.
* מחוון "אישרו הגעה" במסך הצינתוקים.
* מתג הפעלה + שדה שלוחה בהגדרות.
* הפונקציה `runRsvpCampaign()` ב-`src/yemot.js`.

**מה נדרש להשלמה (צד ימות המשיח):**

1. צרו במערכת שלכם **שלוחה** (לדוגמה `/5`) עם הודעה מוקלטת:
   *"למכירת המשקפיים היום — להקשה 1 אם אתם מגיעים, 2 אם לא."*
2. הגדירו את השלוחה כ-`type=get_input` השומרת את ההקשה
   (לדוגמה לקובץ `ivr2:/5/rsvp.ini` או בשליחה ל-API חיצוני דרך `api_url`).
3. הזינו את נתיב השלוחה בשדה **"שלוחת אישורי ההגעה"** בהגדרות וסמנו **"הפעלת קמפיין אישורי הגעה"**.
4. לקליטת התשובות אוטומטית, הוסיפו ל-`src/yemot.js` פונקציה שקוראת את הקובץ
   באמצעות `DownloadFile` / `GetIVR2Dir` ומעדכנת את שדה `rsvp` של הנמענים.

עד להשלמה — ניתן לעדכן את אישורי ההגעה ידנית במסך **צינתוקים → פירוט**.

## 6. פתרון תקלות

| תסמין | סיבה סבירה | פתרון |
|---|---|---|
| `Failed to fetch` / שגיאת CORS | קריאה ישירה מהדפדפן | עברו למצב "שרת ביניים" |
| `responseStatus: "UNAUTHORIZED"` | טוקן שגוי | בדקו מספר מערכת + סיסמת API |
| `שגיאת תקשורת (404)` | שם פעולה שגוי או שרת הביניים לא פרוס | ודאו שהאתר פרוס בסביבה התומכת בפונקציות |
| הצינתוק לא יוצא | אין יחידות בחשבון / `callerId` לא מאושר | בדקו במערכת ימות המשיח |
| נשלח לאף אחד | כל המספרים נפסלו בנרמול | בדקו שהעמודה "טלפון" מכילה מספרים ישראליים תקינים |

**טיפ:** לפני שליחה אמיתית — סמנו **"הרצת בדיקה"** בחלון השליחה.
הקמפיין יירשם ביומן עם כל הנמענים, אך לא יישלח בפועל.
