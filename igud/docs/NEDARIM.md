# חיבור נדרים פלוס

הטפסים של האיגוד יושבים בנדרים פלוס, ומולאו בעמדות ובאתר. המסמך הזה
מתאר איך הרשומות שלהם נכנסות למאגר.

הכתוב כאן נשען על התיעוד הרשמי של נדרים פלוס. אפשר לעיין בו בממשק:
**עוד ← תיעוד API**, או בכתובת `https://reports.matara.pro/more/api`.

---

## כללי היסוד של ה-API

ארבעה כללים שקובעים את כל מה שבא אחריהם:

| הכלל | הפירוט |
| --- | --- |
| מספר המוסד | בפעולות הטפסים וה-Reports הפרמטר הוא `MosadId`. `Mosad` שייך לאייפרם ולדף התשלום בלבד |
| האימות | `ApiPassword` — המפתח שמתחיל ב-`npk_`. נוצר בממשק במסך **עוד ← מפתחות API** |
| `ApiValid` | סיסמת דף התשלום. **אינה** משמשת את משיכת הטפסים, ונשמרת אצלנו רק לשימוש עתידי |
| מבנה התשובה | בדרך כלל JSON, אבל שגיאה עלולה לחזור כטקסט חשוף. הקוד מנסה לפרסר, ואם נכשל מתייחס לתשובה כהודעת שגיאה |

תאריכים בכל הפעולות: `dd/MM/yyyy`.

---

## הדרך העיקרית: משיכת הרשומות

זו הדרך הרשמית, והיא אינה דורשת שום הגדרה בצד של נדרים פלוס — רק מפתח API.

```
POST https://matara.pro/nedarimplus/Forms/Manage.aspx
```

| פרמטר | הערך אצלנו |
| --- | --- |
| `Action` | `GetJson` |
| `MosadId` | מספר המוסד מההגדרות |
| `ApiPassword` | המפתח `npk_…` מההגדרות |
| `TofesId` | `4320` / `4063` / `4018` / `4357` |
| `MaxId` | `500` — המרב שהשרת מאפשר בקריאה אחת |
| `LastId` | הסמן: מזהה הרשומה האחרונה שנקלטה |
| `GetJsonParam` | אובייקט JSON של שמות העמודות: `Field1`, `Field2`, וכן הלאה |

### הסמן

בכל סנכרון נמשכות רק רשומות שנוספו מאז הפעם הקודמת. הסמן הוא ה-`ID`
הגבוה ביותר שהתקבל, והוא נשמר בהגדרות תחת `forms.<מספר הטופס>.lastId`.
המשיכה רצה בלולאה עד שחוזר מערך ריק, כפי שהתיעוד מנחה.

לחיצה על **איפוס ומשיכה** במסך הניהול מאפסת את הסמן ומושכת הכול מחדש.
זה בטוח: רשומה שכבר נקלטה מזוהה לפי המזהה שלה ומתעדכנת במקום להיכפל.

### הפעלה

במסך הניהול, לשונית **חיבורים והגדרות**:

- **סנכרון כל הטפסים** — מושך את כל הטפסים המסומנים כפעילים.
- **משיכה** ליד טופס מסוים — מושך רק אותו.

או ישירות:

```
POST /api/nedarim/pull
Authorization: Bearer <אסימון של מנהל>
Content-Type: application/json

{ "form": "4320", "reset": false }
```

## מספור השדות, ואיך מוודאים אותו

נדרים פלוס מחזירים את שדות הטופס בשמות `Field1`, `Field2` וכן הלאה.
ההתאמה בין המספר לבין המשמעות נקבעת לפי סדר השדות בטופס, וסדר זה זהה
לסדר העמודות בייצוא לאקסל — ומשם נלקחו התוויות בקובץ `lib/nedarim-forms.ts`.

מכיוון שאסור להסתמך על הנחה, יש כפתור **בדיקת שדות** ליד כל טופס:
הוא מושך רשומה אחת אחרונה ומציג טבלה של שלוש עמודות — מספר השדה,
התווית הצפויה, והערך שהתקבל בפועל. אם הם מתאימים זה לזה, המספור נכון.

אם הערכים מוסטים בשדה אחד, משנים את **מספר השדה הראשון** (`fieldBase`)
ובודקים שוב. אין צורך לגעת בקוד.

> את שמות העמודות המדויקים אפשר לראות גם בממשק נדרים פלוס:
> **ניהול טפסים ← הצג רשומות ← כפתור API**.

### למה הפירוש אמין

הרשומה שמתקבלת מה-API משוחזרת לשורת גיליון, ומשם היא עוברת באותם
מנתחים שמשרתים את הייבוא מקובץ אקסל. כך יש גרסה אחת של כללי הפירוש,
ולא שתיים שנוטות להיפרד. השחזור נבדק מול 131 הרשומות האמיתיות של
ארבעת הטפסים, והפירוש יצא זהה לחלוטין לפירוש הישיר מהגיליון.

## הדרך המשלימה: callback

נדרים פלוס יכולים לדחוף כל טופס בזמן אמת. את הכתובת מוסרים למחלקת
הטפסים שלהם:

```
POST https://<כתובת האתר>/api/nedarim/callback
```

**אימות** — במסך הניהול ממלאים **סוד ה-callback**, ונדרים פלוס שולחים
אותו בכותרת `x-igud-secret` או בשדה `secret` בגוף הפנייה.

**מבנה הפנייה** — `FormId` ובתוכו `Data`. שני מבנים נתמכים לשדות:
שמות מפורשים (`RabbiName`, `City` וכדומה), או עמודות `Field1..FieldN`
כפי שהן חוזרות מה-API. במקרה השני הפירוש עובר באותם מנתחים.

**בדיקת חיים** — `GET /api/nedarim/callback?ping=1` מחזירה אישור בלי
לכתוב דבר.

שתי הדרכים חיות זו לצד זו ואינן מתנגשות: המזהה של הרשומה בנדרים פלוס
הוא מפתח ייחודי במאגר, ולכן רשומה שהגיעה פעמיים מתעדכנת ואינה נכפלת.

## מה קורה לרשומה שנקלטה

| הטופס | היעד במאגר | הסטטוס |
| --- | --- | --- |
| 4320 — עדכון שיעור לפרסום | `igud_lessons` + `igud_occurrences` | ממתין לאישור |
| 4063 — בקשה למגיד שיעור | `igud_requests` בסוג `open_lesson` | חדש |
| 4018 — רישום כמגיד שיעור | `igud_requests` בסוג `maggid` | חדש |
| 4357 — חיפוש והרשמה לעדכונים | `igud_subscribers` | פעיל |

**שום רשומה אינה מתפרסמת מאליה.** כל שיעור שנקלט נכנס לתור האישור,
והמנהל מחליט אם לפרסם, להסתיר או למחוק. זו ההגנה על איכות המאגר,
והיא גם רשת הביטחון מול רשומות בדיקה ושמות משובשים שהצטברו בטפסים.

---

## אין פרסום חזרה לנדרים פלוס

בגרסה מוקדמת היה כאן מסלול `push` ששלח את השיעורים בחזרה. הוא הוסר:
ה-API של נדרים פלוס אינו מכיר פעולה כזו, והמסלול פנה לכתובת שאינה
קיימת. הפצת השיעורים החוצה נעשית דרך הממשק הציבורי של האיגוד
(`/api-docs`), שנועד בדיוק לכך.

## שגיאות נפוצות

| ההודעה | המשמעות |
| --- | --- |
| `חסר מפתח API (ApiPassword)` | לא מולא מפתח `npk_` במסך ההגדרות |
| הודעה בעברית מנדרים פלוס | השרת דחה את הפנייה. בדרך כלל מפתח שגוי, מוסד שגוי, או מפתח מוגבל בלי הרשאת "משיכת רשומות טופס" |
| `נדרים פלוס לא החזירו רשימת רשומות` | התשובה לא הייתה מערך. בדרך כלל מספר טופס שאינו שייך למוסד |
| `הפנייה לנדרים פלוס עברה את זמן ההמתנה` | תקלת רשת זמנית. אפשר לנסות שוב, הסמן לא זז |

אם המפתח נוצר עם הרשאות מוגבלות, צריך לסמן לו במסך **עוד ← מפתחות API**
את הפעולה `Manage|GetJson` (משיכת רשומות טופס).
